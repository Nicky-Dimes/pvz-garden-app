# PVZ Garden — Safe art production & deployment pipeline

## Important distinction

**Image-model output** (the approved PNG poster): visual target and inspiration. There is no recoverable source code or deterministic recreation algorithm for that particular image.

**Authentic game sprite:** actual raster authored on a deliberate small logical pixel grid with controlled palette, transparent background, and integer-scaled display. It can be painted in a sprite editor, authored from coordinates via `pvz-pixel-primitives.js`, or generated by suitable tooling and manually cleaned at native pixel level. Code may implement the latter process, but pixel-perfect creative reproduction of dozens of unique characters needs asset authoring/review, not a single global rendering filter.

## Step-by-step

1. **Audit project**, archive state and list authoritative IDs from actual code (not from the poster). Inventory uses the roster's **141 plant species × 3 stages, 81 zombies, 12 bosses** as provisional QA comparison; verify exact current counts, category membership, and whether variants are encoded separately.
2. **Add renderer helpers** without replacing working game logic. Preserve all existing animation, coordinate, collision, and save-data systems. Apply nearest-neighbor to each drawing context after any size reset.
3. **Pick three probes:** one plant's three stages (e.g., Peashooter), basic Zombie walk cycle, one Zomboss. Create genuine transparent native-grid PNGs matching the approved reference. Do not proceed with mass generation yet.
4. **Use the Art Studio** for side-by-side preview and notes. Approve candidates one at a time. The browser page cannot alter repository source by itself; exported reviews go to Claude Code.
5. **Integrate approved assets only** in a development branch/PR. Fallback to old sprites if PNG missing/failed to load. No guessed cropping from the poster. Existing key IDs, hitboxes, collision, attacks, save-state serialization remain unchanged.
6. **Run mobile checks**: iPhone/iPad Safari, installed Home Screen mode, different DPR devices, landscape/portrait, memory and FPS, transparent backgrounds, touch interactions, cache invalidation for updated sprite URLs.
7. **Expand by batches** (few species each), review each before release, preserve release rollback and previous assets.

## GitHub Pages and persistence

- GitHub Pages publishes static files. Browser-only image picker cannot write replacements to repository; manual commit or Claude Code's authenticated repository session needed.
- Browsers isolate localStorage by origin/device. This review tool uses its own namespaced key, completely separate from game saves, and exports JSON so notes can be transferred to Claude.
- Do not hardcode private tokens or GitHub credentials in a publicly deployed Art Studio page.
- A hidden URL on public GitHub Pages is NOT private. Keep Art Studio local/private if review notes/assets should be private.
- If the game has a service worker/PWA cache, audit its strategy; version newly deployed asset URLs to avoid stale sprite images on installed devices. Do not delete browser save data during cache updates.

## Quality checks (objective vs subjective)

**Automated checks CAN:** check PNG file presence, dimensions, filename collisions, duplicate IDs, atlas bounds, alpha mode, consistency of declared source size and frame count.

**Automated checks CANNOT reliably determine:** whether artwork matches reference style, whether legs/anatomy look right, whether facial expression is good, whether the sprite looks like its identity, or whether it has *truly* hand-authored clusters. These require human visual approval.

## Acceptance gates

- Gate A: project audit completed and safe implementation plan documented.
- Gate B: one plant's 3 growth stages matches approved sheet at native size; old game still loads.
- Gate C: basic zombie animation and one Zomboss match sheet style; performance acceptable.
- Gate D: category-by-category sprite migration and no missing IDs or regression.
- Gate E: release tested on Safari / installed web app and recoverable from repository history.
